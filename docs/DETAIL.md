# Follow-up prompts

在输入框上方增加一条「下一步指令建议」栏。

## 行为

1. 一轮回复正常结束时（`turn/end` 且原因为 `completed`，且本轮确有助手输出），插件在后台用当前会话的模型再发一次轻量请求，要求模型返回 JSON：

   ```json
   { "suggestions": [{ "prompt": "Add unit tests for the parser" }] }
   ```

   一条建议只有一段文本：卡片上显示的就是点击 `↑` 发送的内容，不存在「短标题 + 长指令」两套文案。指令控制在 50 字以内，卡片是固定高度的一行，文案完整显示、不需要悬停看全文。

2. 解析结果（最多三条）写入会话日志的自定义事件 `follow-up-prompts/ready`，并由同名 projection `followUpPrompts` 折叠成视图。
3. 输入框上方的插槽 `conversation.input.dock` 渲染这些建议：
   - 点击左侧文案：把这条指令填入输入框，由你自己继续编辑（会替换当前草稿）。
   - 文案完整显示，不截断、不加省略号，也不换行；卡片高度固定，宽度由文案长度决定，所以几条并排时宽度不一致。
   - 点击 `↑`：直接发送卡片上的这条指令；宿主正忙（审批、提交中）时只填入不发送。
   - 建议放不下时，两端出现圆形箭头：点右侧 `›` 横向滑到最右，滑到最右后左侧出现 `‹`，点它回到最左。箭头只在对应方向确实还有内容时出现，滚动条本身隐藏。
   - 收起：鼠标悬停在建议条上时右侧出现 `×`，点击收起本轮建议；按 `Esc` 同样收起。收起状态只对当前这一轮生效，新一轮会重新显示。

代理运行期间不显示建议；新一轮开始时上一轮的建议会被清空并取消未完成的模型请求，因此不会闪回上一条。子会话（`session.header.origin === 'subagent'`）不产生建议，避免放大请求量。

## 数据与隐私

建议文本随会话日志持久化，因此重新打开会话仍能看到历史建议。发给模型的上下文只包含本轮用户请求与助手回答的截断片段（用户 2000 字、助手 4000 字）。

## 配置

当前无用户可配项；请求使用本轮实际使用的 provider/model 与推理强度，20 秒超时，失败时静默跳过，不影响对话。
