# Follow-up prompts

在输入框上方增加一条「下一步指令建议」栏。

## 行为

1. 一轮回复正常结束时（`turn/end` 且原因为 `completed`，且本轮确有助手输出），插件在后台用当前会话的模型再发一次轻量请求，要求模型返回 JSON：

   ```json
   { "suggestions": [{ "prompt": "Add unit tests for the parser" }] }
   ```

   一条建议只有一段文本：卡片上显示的就是点击 `↑` 发送的内容，不存在「短标题 + 长指令」两套文案。指令控制在 40 字以内；超过 40 字时卡片只显示前 40 个字符加省略号，完整文案在悬停浮层里给出。

2. 解析结果（最多三条）写入会话日志的自定义事件 `plugin:dsh-follow-up-prompts/ready`，并由 projection `followUpPrompts` 折叠成视图。

   事件信封必须带 `ignorable: true`：DSH 持久化层只接受核心白名单里的类型，或带该标记的外部事件；缺标记时读取端会拒绝解释整份会话日志（表现为「历史加载失败」）。同时外部类型要用 `plugin:` 前缀。1.0.0 及更早版本写的 `follow-up-prompts/ready` 仍在折叠范围内，升级后历史建议照常显示。
3. 输入框上方的插槽 `conversation.input.dock` 渲染这些建议：
   - 点击左侧文案：把这条指令填入输入框，由你自己继续编辑（会替换当前草稿）。
   - 卡片是固定高度的一行，不换行；40 字以内完整显示，超出则截断成 `…`。卡片宽度由文案长度决定，所以几条并排时宽度不一致。
   - 悬停浮层：鼠标停在卡片上约 0.25 秒，卡片上方浮出完整文案与操作规则（`点击添加到输入框（双击以选择并发送）· ↑ 立即发送`）。浮层宽度随内容，最宽与对话框一致，文案多长都完整展示、不限行数；浮层不拦截鼠标，移开即消失，键盘聚焦卡片时同样出现。
   - 双击卡片文案：跳过「先填入再编辑」，直接发送这条指令（与点 `↑` 等价）。因此单击会有约 0.25 秒的判定延迟。
   - 点击 `↑`：直接发送卡片上的这条指令；宿主正忙（审批、提交中）时只填入不发送。
   - 建议放不下时，两端出现圆形箭头：点右侧 `›` 横向滑到最右，滑到最右后左侧出现 `‹`，点它回到最左。箭头只在对应方向确实还有内容时出现，滚动条本身隐藏。
   - 收起：鼠标悬停在建议条上时右侧出现 `×`，点击收起本轮建议；按 `Esc` 同样收起。收起状态只对当前这一轮生效，新一轮会重新显示。右侧还有没展示的建议（出现 `›`）时，`×` 先不显形——两者占同一个位置，避免叠在一起；滑到最右、`›` 消失后，悬停即可看到 `×`。

代理运行期间不显示建议；新一轮开始时上一轮的建议会被清空并取消未完成的模型请求，因此不会闪回上一条。子会话（`session.header.origin === 'subagent'`）不产生建议，避免放大请求量。

## 数据与隐私

建议文本随会话日志持久化，因此重新打开会话仍能看到历史建议。发给模型的上下文只包含本轮用户请求与助手回答的截断片段（用户 2000 字、助手 4000 字）。

## 兼容性

写入会话日志用的是 DSH 的内部方法（`session.publicationEntry()` 与 `session.commit()`），没有对外契约。升级 DSH 后如果这些方法变了，插件的表现是「建议不再出现」，而不是崩溃或写坏日志：

- 首次发现写入面缺失就跳过模型请求，并在宿主日志留一条 `[dsh-follow-up-prompts]` 告警；
- 任何写入失败只记一条诊断，不会留下半截事件；
- 事件始终带 `ignorable`，读取端认不出时跳过，不会让会话打不开；
- `engines.dsh` 限定在已实测的大版本内（`>= 0.2.2-rc.5 < 0.3.0`），跨大版本时由 DSH 在安装/启用阶段拦下。

写入面不可用时，建议条位置显示一行「建议功能不可用」，悬浮可见原因；这条状态只存在内存里，由 projection 的 `wire.view` 带给客户端，不写事件、也不进 checkpoint——否则旧会话恢复时会读到当时的结论。`DSH_FOLLOW_UP_PROMPTS_FORCE_UNAVAILABLE=1` 可以强制这个状态，用来在界面上核对样式。

这条提示能到界面，靠的是投影状态里那个 `rev` 计数：DSH 只在 `apply` 返回新 state 引用时才重算 `wire.view`，而「写入面是否可用」是运行期状态、不会产生事件。所以 `apply` 对每条事件都推进 `rev`（视图内容没变时 `wire.view` 复用同一个对象，不会惊动客户端）。去掉它，提示行就再也不会出现——自检里专门有一条断言守这个行为。

升级后可以跑仓库里的自检：`npm run canary`（只读扫描会话日志，非 0 退出码表示存在会让会话打不开的事件）与 `npm run selftest`（假宿主验证写入面可用/缺失/抛错三条路径）。

## 配置

当前无用户可配项；请求使用本轮实际使用的 provider/model 与推理强度，20 秒超时，失败时静默跳过，不影响对话。
